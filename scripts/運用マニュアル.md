
# 運用マニュアル

FlashBuy の AWS 環境を停止・再開する手順。
手順の実行方法、実行後の状態、**作り直しで変わる URL** をまとめる。

対象スクリプト: `scripts/spindown.sh` / `scripts/spinup.sh`
---

## 1. これは何か

FlashBuy の AWS 環境は、使わない間まるごと削除してコストを止められる。

| 状態 | 月額の目安 |
|---|---|
| 稼働中（spinup 済み） | 約 $76 |
| 停止中（spindown 済み） | 約 $1 |

削除と再構築は Terraform で行うため、**コードや設定を書き換える必要はない**。
`spindown.sh` は依存関係の逆順に destroy し、`spinup.sh` は依存関係の順に apply する。

## 2. 前提

| 必要なもの | 用途 |
|---|---|
| `terraform` | 全モジュールの apply / destroy |
| `aws` CLI | 認証確認、S3 sync、ECR ログイン、残存リソース確認 |
| `docker` | API イメージの build / push（linux/arm64） |
| `pnpm` または `corepack` | フロントエンドの build |
| `terraform/{data,lambda,compute,monitoring}/terraform.tfvars` | 4 つすべて必須。無いと即エラー終了 |

AWS の認証情報は、対象アカウントのものが有効になっていること。
スクリプトは開始時に `aws sts get-caller-identity` でアカウント ID を表示する。**まずここで意図したアカウントか確認する。**

## 3. 停止する（spindown.sh）

```bash
# 確認プロンプトあり（'flashbuy' と入力）
bash scripts/spindown.sh

# プロンプトなし（CI・自動化向け）
bash scripts/spindown.sh --yes

# CloudFront と S3 も削除する（既定では残す）
DESTROY_FRONTEND=1 bash scripts/spindown.sh
```

### 何が消えるか

| モジュール | 消えるもの | 月額の目安 |
|---|---|---|
| `data` | RDS、ElastiCache、VPC、サブネット、IGW、EIP 4 本 | 約 $54 |
| `compute` | ALB、ECS サービス／クラスタ、ECR リポジトリ | 約 $23 |
| `lambda` | Lambda 2 関数、EventBridge ルール、Scheduler グループ、SNS | 約 $0 |
| `monitoring` | CloudWatch アラーム 12 本、ダッシュボード | 約 $0.2 |

`frontend`（CloudFront 2 本 + S3 2 つ）は**既定では削除しない**。月額が約 $0 で、残しておけば公開 URL が変わらないため。消したい場合だけ `DESTROY_FRONTEND=1` を付ける。

### 月額 約 $0 なのに `lambda` / `monitoring` を消す理由

コストではなく、技術的な制約。

- **`lambda`** — `data` の private subnet に ENI を持つ（`terraform/lambda/main.tf:132-135`）。関数を残したまま VPC を削除すると、サブネットが ENI 残存で削除できず `data` の destroy が失敗する。加えて DB が無い状態で 1 分ごとの cron が走り、毎回エラーになる。
- **`monitoring`** — ALB / RDS / Redis / Lambda を data source で名前引きしている（`terraform/monitoring/main.tf:15-39`）。参照先を先に消すと、次に `monitoring` を destroy しようとしたとき plan の時点で参照解決に失敗し、削除できなくなる。

### 何が残るか

`state` / `shared` / `auth` / `storage` / `frontend`。

**`auth`（Cognito）は絶対に消さない。** User Pool を作り直すとユーザーの `sub` が変わり、`api/init_db.sql` に固定値で書かれた UUID と一致しなくなる。DB を作り直してもデモユーザーでログインできなくなるため、スクリプト側でも削除対象から外してある。

`storage`（商品画像の S3）も残す。ユーザーがアップロードした画像が消えるため。

### 実行中の挙動

1. 二重確認（`flashbuy` の入力。`--yes` で省略可）
2. S3 バケットを空にする（バージョンと削除マーカーも含む。`prod` バケットは `force_destroy = false` のため、空にしないと `BucketNotEmpty` で失敗する）
3. RDS の `deletion_protection` と `prevent_destroy` を一時的に外す（`trap` により、失敗しても必ず元に戻る）
4. `monitoring` → `frontend` → `compute` → `lambda` → `data` の順に destroy
5. AWS CLI で 10 種類のリソースを実査し、残存があれば警告

**RDS のデータは消える。最終スナップショットは取得されない。** 再開時に `api/init_db.sql` で作り直す前提。

**冪等。** 途中で失敗しても、そのまま再実行してよい。削除済みのモジュールは自動でスキップされる。

所要時間の目安: 15〜25 分。

### 実行後の状態

- API・画面ともにアクセス不可
- RDS / Redis / ALB / ECS / Lambda / CloudFront は存在しない
- Cognito のユーザー、S3 の画像、Terraform の state は残っている

## 4. 再開する（spinup.sh）

```bash
bash scripts/spinup.sh
```

引数・オプションは無い。

### 実行順（変えると失敗する）

| # | 処理 | 備考 |
|---|---|---|
| 1 | グローバル IP と `allowed_admin_cidrs` の整合確認 | 不一致だと手元から RDS に接続できず、DB 初期化に失敗する。対話で続行可否を聞かれる |
| 2 | Lambda の zip をビルド | `build.sh` 内で `go test` も走る |
| 3 | `data` を apply | **RDS 作成に 8〜10 分** |
| 4 | `lambda` を apply | `data` の private subnet を参照 |
| 5 | `compute` を ECR のみ apply | `-target=aws_ecr_repository.api` |
| 6 | API イメージを build & push | `config-prod.yaml.example` を無条件でコピーしてから build |
| 7 | `compute` を全体 apply | ALB・ECS サービス。起動しない場合は `--force-new-deployment` で 1 回だけ再試行 |
| 8 | `api/init_db.sql` を投入 | `psql` が無ければ `postgres:15-alpine` コンテナで代用 |
| 9 | `frontend` を apply → S3 sync → CloudFront invalidate | ALB の DNS が変わっているため、origin を貼り直す必要がある |
| 10 | `monitoring` を apply | ALB / RDS / Lambda を名前で参照するため最後 |
| 11 | 変更された値を表示 | CloudFront の ID、SNS の再購読 |
| 12 | `http://<ALB>/ping` で疎通確認 | |

Terraform の apply は一時的なネットワーク障害で落ちることがあるため、各 apply は最大 3 回まで自動再試行する（10 秒間隔）。

所要時間の目安: 20〜30 分（RDS の作成待ちが大半）。

### 実行後の状態

- 画面と API が利用可能になる
- DB は `init_db.sql` のシードデータで初期化済み（**既存データは消える**）
- デモアカウント:
  - `admin@flashbuy.demo`（管理者）
  - `user@flashbuy.demo`（一般）
  - パスワードは両方 `Demo1234!`
- CloudWatch のログは空（ロググループごと作り直されるため）

## 5. 作り直しで変わる URL

CloudFront に独自ドメインを設定しておらず（`cloudfront_default_certificate = true`、`aliases` なし）、ドメイン名は AWS がディストリビューションごとに割り当てるランダム文字列になっている。

**既定の `spindown.sh` は `frontend` を残すため、この URL は変わらない。** 変わるのは `DESTROY_FRONTEND=1` を付けて CloudFront まで消した場合だけ。

| 項目 | 既定の spindown（frontend を残す） | `DESTROY_FRONTEND=1` | 理由 |
|---|---|---|---|
| CloudFront ドメイン（`*.cloudfront.net`） | 変わらない | **変わる** | ディストリビューションを作り直すと新しいランダム名が割り当てられる |
| CloudFront ディストリビューション ID | 変わらない | **変わる** | 同上。GitHub Secret の更新が必要 |
| ALB の DNS 名 | **変わる** | **変わる** | `compute` は必ず削除される。保持するオプションは無い |
| S3 バケット名 | 変わらない | 変わらない | `flashbuy-frontend-{env}-{アカウントID}` で固定 |
| RDS のエンドポイント | **変わる** | **変わる** | インスタンスを作り直すため |
| ElastiCache のエンドポイント | **変わる** | **変わる** | 同上 |
| ECR リポジトリ URL | 変わらない | 変わらない | アカウント ID・リージョン・リポジトリ名から決まる |
| Lambda の ARN | 変わらない | 変わらない | 関数名が固定のため |
| SNS トピックの ARN | 変わらない | 変わらない | トピック名が固定のため（ただし購読は消える） |
| Cognito User Pool | 変わらない | 変わらない | `auth` は削除対象外 |

### URL は残るが、API は止まる

`frontend` を残しても、`/api/*` の転送先である ALB は `compute` に属するため必ず消える。停止中は**画面は開くが、商品一覧の取得や購入は失敗する**。

`spinup.sh` の手順 9 で `frontend` を apply し直し、新しい ALB に origin を貼り替えるので、再開後は自動的に復旧する。

### 再開後に必要な作業

`spinup.sh` の最後に、変更された値が表示される。**frontend を残した場合は CloudFront の ID が変わらないため、GitHub Secret の更新は不要**（スクリプトが state を見て判定し、その旨を表示する）。

1. **CloudFront のディストリビューション ID**（`DESTROY_FRONTEND=1` で消した場合のみ）
   ```
   CLOUDFRONT_DISTRIBUTION_ID_DEV
   CLOUDFRONT_DISTRIBUTION_ID_PROD
   ```
   古い ID のままだと `frontend.yml` のキャッシュ削除（invalidate）が失敗する。`S3_BUCKET_DEV` はアカウント ID 由来なので変更不要。

2. **SNS のメール購読をやり直す**
   `monitoring` を作り直すと購読が消えるため、確認メールのリンクをもう一度クリックする。

3. **`api/config-dev.yaml` を使っている場合、値を更新する**
   ローカルから API を起動して開発する場合は、RDS のホストと Redis のホストを新しい値に書き換える。

4. **画像アップロードが CORS で失敗する場合**
   `frontend` を作り直すと CloudFront のドメインが変わる。`storage` は削除されないため、
   CORS の許可オリジンが古いドメインのまま残っている。
   `terraform/storage/terraform.tfvars` の `allowed_origins` に新しい URL を追加して
   `terraform -chdir=terraform/storage apply` を実行する。

   確認方法（許可済みなら `Access-Control-Allow-Origin` が返る）:
   ```bash
   curl -i -X OPTIONS "https://flashbuy-images-dev.s3.ap-northeast-1.amazonaws.com/products/test.png" \
     -H "Origin: https://<現在のCloudFrontドメイン>" \
     -H "Access-Control-Request-Method: PUT" \
     -H "Access-Control-Request-Headers: content-type"
   ```


## 6. トラブル時

| 症状 | 対処 |
|---|---|
| `terraform.tfvars がありません` | 4 つのモジュールすべてに必要。`.example` をコピーして値を埋める |
| `*.zip がありません`（spindown 時） | `destroy` でも plan 時に zip を参照する。`bash lambdas/*/build.sh` を先に実行する |
| `BucketNotEmpty` で destroy 失敗 | スクリプトは最初にバケットを空にする。それでも失敗する場合はバケット名の接頭辞と `tfvars` の `project_name` が一致しているか確認する |
| `DeleteVpc` が `DependencyViolation` で失敗 | VPC 内に Terraform 管理外のセキュリティグループが残っている。スクリプトは CloudShell 由来のものを自動で片付けるが、手動作成したものは手で消す |
| ECS タスクが起動しない | CloudWatch Logs の `/ecs/flashbuy-api-dev` を確認する。DB 接続失敗が多い |
| DB 初期化で接続できない | グローバル IP が `allowed_admin_cidrs` に入っているか確認する |
| 画面は開くが API が失敗する | `frontend` の apply が済んでいるか確認する。ALB の DNS が変わっている可能性がある |

## 1. 这是什么

FlashBuy 的 AWS 环境可以整体删除来停止计费。

| 状态 | 月费 |
|---|---|
| 运行中（已 spinup） | 约 $76 |
| 已停止（已 spindown） | 约 $1 |

删除和重建都由 Terraform 完成，**不需要改代码或配置**。`spindown.sh` 按依赖倒序 destroy，`spinup.sh` 按依赖正序 apply。

## 2. 前提

| 需要 | 用途 |
|---|---|
| `terraform` | 所有模块的 apply / destroy |
| `aws` CLI | 认证检查、S3 sync、ECR 登录、残留资源检查 |
| `docker` | 构建推送 API 镜像（linux/arm64） |
| `pnpm` 或 `corepack` | 构建前端 |
| `terraform/{data,lambda,compute,monitoring}/terraform.tfvars` | 四个都必须有，缺一个直接报错退出 |

AWS 凭证要对准目标账号。脚本启动时会用 `aws sts get-caller-identity` 打印账号 ID，**先确认是不是你想操作的那个账号**。

## 3. 停止（spindown.sh）

```bash
# 有确认提示（需输入 'flashbuy'）
bash scripts/spindown.sh

# 跳过提示
bash scripts/spindown.sh --yes

# 连 CloudFront 和 S3 一起删（默认是保留）
DESTROY_FRONTEND=1 bash scripts/spindown.sh
```

### 会删什么

| 模块 | 删掉的内容 | 月费 |
|---|---|---|
| `data` | RDS、ElastiCache、VPC、子网、IGW、4 个 EIP | 约 $54 |
| `compute` | ALB、ECS 服务/集群、ECR 仓库 | 约 $23 |
| `lambda` | 2 个 Lambda、EventBridge 规则、Scheduler 组、SNS | 约 $0 |
| `monitoring` | 12 个 CloudWatch 告警、Dashboard | 约 $0.2 |

`frontend`（2 个 CloudFront + 2 个 S3）**默认不删**。月费约 $0，留着公开 URL 就不会变。只有显式设 `DESTROY_FRONTEND=1` 才删。

### 月费约 $0，为什么还是删了 lambda / monitoring

不是成本考虑，是技术约束。

- **`lambda`** — 在 `data` 的 private subnet 里有 ENI（`terraform/lambda/main.tf:132-135`）。函数留着不删，VPC 就因为子网上还有 ENI 而删不掉，`data` 的 destroy 会失败。另外 DB 已经没了，1 分钟一次的 cron 会一直跑一直报错。
- **`monitoring`** — 用 data source 按名字查 ALB / RDS / Redis / Lambda（`terraform/monitoring/main.tf:15-39`）。引用目标先被删掉的话，下次想 destroy `monitoring` 时，plan 阶段就会因为查不到资源而失败，等于把自己卡死。

### 会留什么

`state` / `shared` / `auth` / `storage` / `frontend`。

**`auth`（Cognito）绝对不能删。** User Pool 重建后用户的 `sub` 会变，和 `api/init_db.sql` 里写死的 UUID 对不上，DB 重建了也登不进去。脚本已经把它排除在删除范围外。

`storage`（商品图 S3）也保留，里面有用户上传的图片。

### 执行过程

1. 二次确认（输入 `flashbuy`，`--yes` 可跳过）
2. `DESTROY_FRONTEND=1` 时先清空 S3 桶（含历史版本和删除标记；`prod` 桶是 `force_destroy = false`，不清空会 `BucketNotEmpty` 失败）
3. 临时摘掉 RDS 的 `deletion_protection` 和 `prevent_destroy`（`trap` 保证失败也会还原）
4. 默认按 `monitoring` → `compute` → `lambda` → `data` 顺序 destroy（`DESTROY_FRONTEND=1` 时在 `monitoring` 后多一步 `frontend`）
5. 用 AWS CLI 实查 10 类资源，有残留就告警

**RDS 数据会丢，不取最终快照。** 前提是重建时用 `api/init_db.sql` 重新灌。

**幂等。** 中途失败直接重跑，已删的模块会自动跳过。

耗时约 15~25 分钟。

### 执行后的状态

- API 不可访问（ALB 已删）
- 页面可以打开（CloudFront + S3 还在），但 `/api/*` 返回错误
- RDS / Redis / ALB / ECS / Lambda / ECR 都不存在
- 默认保留：Cognito 用户、S3 图片、Terraform state、CloudFront 与前端 S3

## 4. 启动（spinup.sh）

```bash
bash scripts/spinup.sh
```

无参数、无选项。

### 执行顺序（改了会失败）

| # | 步骤 | 说明 |
|---|---|---|
| 1 | 检查公网 IP 是否在 `allowed_admin_cidrs` 里 | 不在的话本机连不上 RDS，DB 初始化会失败。会交互询问是否继续 |
| 2 | 构建 Lambda zip | `build.sh` 里会跑 `go test` |
| 3 | apply `data` | **创建 RDS 要 8~10 分钟** |
| 4 | apply `lambda` | 引用 `data` 的 private subnet |
| 5 | 只 apply `compute` 的 ECR | `-target=aws_ecr_repository.api` |
| 6 | 构建推送 API 镜像 | 先无条件覆盖 `config-prod.yaml.example` 再 build |
| 7 | apply `compute` 全量 | ALB + ECS。起不来会用 `--force-new-deployment` 重试一次 |
| 8 | 灌 `api/init_db.sql` | 没有 `psql` 就用 `postgres:15-alpine` 容器 |
| 9 | apply `frontend` → S3 sync → CloudFront invalidate | ALB 的 DNS 变了，必须重贴 origin |
| 10 | apply `monitoring` | 靠名字查 ALB/RDS/Lambda，必须最后 |
| 11 | 打印变更的值 | CloudFront ID、SNS 需重新订阅 |
| 12 | `http://<ALB>/ping` 验活 | |

个 apply 最多自动重试 3 次（间隔 10 秒），应对临时网络故障。

耗时约 20~30 分钟，大头是等 RDS。

### 执行后的状态

- 页面和 API 可用
- DB 已用 `init_db.sql` 的种子数据初始化（**原有数据已清空**）
- 演示账号：
  - `admin@flashbuy.demo`（管理员）
  - `user@flashbuy.demo`（普通）
  - 密码都是 `Demo1234!`
- CloudWatch 日志是空的（日志组随重建一起换新）

## 5. 重建后会变的地址

**这是最需要注意的地方。** CloudFront 没有配自定义域名（`cloudfront_default_certificate = true`，无 `aliases`），域名是 AWS 给每个 distribution 分配的随机串。**默认的 `spindown.sh` 会保留 `frontend`，所以这个 URL 不变。** 只有显式设 `DESTROY_FRONTEND=1` 把 CloudFront 一起删掉时才会变。

| 项 | 默认 spindown（保留 frontend） | `DESTROY_FRONTEND=1` | 原因 |
|---|---|---|---|
| CloudFront 域名（`*.cloudfront.net`） | 不变 | **会变** | 重建 distribution 会分配新的随机名 |
| CloudFront Distribution ID | 不变 | **会变** | 同上。需要更新 GitHub Secret |
| ALB 的 DNS | **会变** | **会变** | `compute` 必删，没有保留开关 |
| S3 桶名 | 不变 | 不变 | `flashbuy-frontend-{env}-{账号ID}`，固定 |
| RDS endpoint | **会变** | **会变** | 实例重建 |
| ElastiCache endpoint | **会变** | **会变** | 同上 |
| ECR 仓库 URL | 不变 | 不变 | 由账号、区域、仓库名决定 |
| Lambda ARN | 不变 | 不变 | 函数名固定 |
| SNS topic ARN | 不变 | 不变 | topic 名固定（但订阅会没） |
| Cognito User Pool | 不变 | 不变 | `auth` 不在删除范围 |

### URL 还在，但 API 会断

`frontend` 留着，`/api/*` 的转发目标 ALB 却属于 `compute`，必删。所以停止期间**页面能打开，但商品列表和购买都会失败**。

`spinup.sh` 第 9 步会重新 apply `frontend`，把 origin 贴到新的 ALB 上，重启后自动恢复。

### 重启后要做的事

`spinup.sh` 结束时会把变更的值打出来。**frontend 保留的情况下 CloudFront ID 没变，不需要更新 GitHub Secret**（脚本会看 state 判断，并直接告诉你）。

1. **CloudFront Distribution ID**（只有 `DESTROY_FRONTEND=1` 删过才需要）
   ```
   CLOUDFRONT_DISTRIBUTION_ID_DEV
   CLOUDFRONT_DISTRIBUTION_ID_PROD
   ```
   留着旧 ID 的话 `frontend.yml` 的缓存清理（invalidate）会失败。`S3_BUCKET_DEV` 由账号 ID 派生，不用改。

2. **重新订阅 SNS 邮件**
   `monitoring` 重建后订阅会没，需要再点一次确认邮件里的链接。

3. **用 `api/config-dev.yaml` 的话要更新值**
   本地起 API 开发的话，RDS host 和 Redis host 要改成新的。

4. **图片上传报 CORS 错误**
   `frontend` 重建后 CloudFront 域名变了，但 `storage` 不会被删，CORS 白名单还停在旧域名。
   把新 URL 加进 `terraform/storage/terraform.tfvars` 的 `allowed_origins`，再跑
   `terraform -chdir=terraform/storage apply`。

   验证（配对了会返回 `Access-Control-Allow-Origin`）:
   ```bash
   curl -i -X OPTIONS "https://flashbuy-images-dev.s3.ap-northeast-1.amazonaws.com/products/test.png" \
     -H "Origin: https://<当前 CloudFront 域名>" \
     -H "Access-Control-Request-Method: PUT" \
     -H "Access-Control-Request-Headers: content-type"
   ```


## 6. 常见故障

| 症状 | 处理 |
|---|---|
| `terraform.tfvars がありません` | 四个模块都要有。复制 `.example` 填值 |
| `*.zip がありません`（spindown 时） | `destroy` 的 plan 也会读 zip。先跑 `bash lambdas/*/build.sh` |
| `BucketNotEmpty` 导致 destroy 失败 | 脚本会先清桶。还失败就检查桶名前缀和 tfvars 里的 `project_name` 是否一致 |
| `DeleteVpc` 报 `DependencyViolation` | VPC 里有 Terraform 管不到的安全组。脚本会自动清理 CloudShell 遗留的，手工建的得手动删 |
| ECS 任务起不来 | 看 CloudWatch Logs 的 `/ecs/flashbuy-api-dev`，多半是 DB 连接失败 |
| DB 初始化连不上 | 确认公网 IP 在 `allowed_admin_cidrs` 里 |
| 页面能开但 API 报错 | 确认 `frontend` 已经 apply 过。ALB 的 DNS 很可能变了 |
